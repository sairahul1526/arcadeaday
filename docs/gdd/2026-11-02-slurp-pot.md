## 2. Controls

### 2.1 Input model (one model for touch, mouse, keys and bots)
Logic receives one input per fixed step: `inp = { x, z, m }` (unit direction on the ground plane, magnitude `m ∈ [0,1]`). Touch/mouse produce it from a floating stick; keys from WASD/arrows; bots and `__qaInput` write it directly. Screen up = world −z.

**Floating relative-drag stick (touch and mouse, identical):**
- Pointer down anywhere outside a UI button → `anchor = (px, py)` (CSS px). No visible stick until the finger moves ≥ the dead-zone.
- `RAD = clamp(0.10 × min(W, H), 34, 64)` CSS px. Dead-zone `DZ = 4` px.
- Offset `o = pointer − anchor`, `|o| = d`. If `d > RAD`: the anchor is dragged along (`anchor += o × (1 − RAD/d)`) so reversing direction is instant (re-anchoring; no need to swipe back across).
- Direction `dir = o / d`. Magnitude `m = clamp((d − DZ) / (0.55 × RAD − DZ), 0, 1)`. So the inner 55 % of the radius is a proportional **precision zone** (creep up to pens, fragile stacks, gate gaps); beyond it is full speed.
- Pointer up / cancel → `m = 0` immediately. **Lost-pointerup guard:** if no pointermove/up for 2.0 s while held and `pointerType === 'touch'`, treat as released (PLAYBOOK lesson).
- Visual: anchor ring (radius RAD, 2u stroke, `#FFF6E3` at 22 % alpha) + knob (radius 0.32 RAD, 55 % alpha) shown while dragging, on L1–L6 and whenever settings "Show stick" is on (default on for touch, off for mouse). Hidden in record/og.
- Multi-touch: only the first pointer steers; others are ignored (no pinch zoom).

**Keyboard:** W/↑, A/←, S/↓, D/→ (any combination, diagonals normalised) → `m = 1`. Space/Enter only act on cards. **P** toggles pause. **Esc** closes the topmost dialog/pause and is **never `preventDefault`ed**. Keydown handler (PLAYBOOK web-shell rule): ignore non-game keys; `if (mode !== 'play' && scrollY > 40) return;`; `preventDefault()` for game keys **before** the `e.repeat` check; never for Esc, Tab, F-keys or modified keys.

### 2.2 Movement (in `logic.js`, frame-rate independent)
```
vMax(r)  = speedOf(r) = min(6.0, 2.5 + 1.2·r)            // u/s  (proto: 2.7 + 1.6·r)
v*       = dir · m · vMax(r)
A        = |v*| < |v| ? A_BRAKE : A_ACC                   // brake faster than accelerate (τ 0.045 / 0.060)
v       += (v* − v) · A                                   // exact exponential follow: no overshoot
                                                          // A_ACC = 1 − exp(−DT/0.060), A_BRAKE = 1 − exp(−DT/0.045),
                                                          // precomputed in consts.js at module load (dt is always DT)
p       += (v + vBelt) · dt
```
- Screen-relative speed: at r 0.3 the pot crosses 0.48 visible-widths/s; at r 2.0, 0.25/s. "Max speed scales gently with size" while the camera zooms out faster, so big pots feel weighty, small pots never feel twitchy.
- Stop distance from full speed: `vMax·τb` = 0.13 u at r 0.3 (rim 0.3), 0.22 u at r 2 (rim 2.0). Zero overshoot by construction (first-order follow).
- Turning 180° at full speed takes ~0.12 s (no orbiting).
- **Braking cue:** when `|v|` drops from > 70 % vMax to < 20 % within 0.15 s, the rim tilts 4° back and two skid puffs spawn (render-only).
- The camera has **no velocity lead** (proto's 0.2 lead made the view drift and caused overshoot judgement errors); see §7.3.

### 2.3 Walls and bounds
- Board bounds: pot centre clamped to `[x0 + 0.5r, x1 − 0.5r] × [z0 + 0.5r, z1 − 0.5r]` (the rim may overhang the board edge by half its radius).
- Solid items the pot cannot swallow block it (§3.4); blocked motion slides along the contact normal (velocity component into the normal is removed), so hugging a hedge row glides instead of sticking.

## 3. Core loop

### 3.1 Units and world
- 1 world unit (u) ≈ 1 m of toy diorama. Ground plane y = 0; the board is a rectangle `[x0, x1] × [z0, z1]`, spawn near `z1` (bottom of screen), boss toward `z0`.
- Map sizes per level: §4 table (16×18 u for L1 up to 34×50 u for L60).
- Every item is a **circle** in logic: footprint radius `a` (u), height `h` (render + occlusion), growth weight `k`, flags. Walls, hedges, fences and car rows are chains of circle items. No polygons in logic.
- Pot: rim radius `r`. Start `r0 = 0.25` (L1, `R0_L1`) / `0.30` (L2–L10, boss levels, twist first levels, Daily, Feast) / `R0_VAR[n % 3]` = 0.30, 0.45 or 0.60 for other levels from L11 (§4.4) / record mode `0.14`. Hard upper bound 4.2.

### 3.2 THE fit rule (one function, everywhere)
```js
// logic.js  (the only definition; never re-implemented)
export const FIT = 0.9;
export const canFit = (rimR, a) => a <= FIT * rimR + 1e-9;   // can a rim of radius rimR swallow footprint a?
export const needR  = a => a / FIT;                          // smallest rim that fits a
```
Callers, all importing from `logic.js`:
| Caller | Use |
|---|---|
| `logic.step` | swallow test `canFit(rEff, item.a)` (rEff includes Mega-rim) and boss test `canFit(w.pot.r, boss.a)` (boss ignores Mega-rim) |
| `logic.step` → `item.fits` flag | per-item boolean `fits[i] = canFit(w.pot.r, ia[i])` recomputed each step for **every** alive item (240 compares, no radius, no viewport); render reads it for rim-light, never recomputes |
| `ui.js` HUD meter | boss silhouette at `meterX(needR(boss.a))`; SIZE UP ticks at `meterX(w.pot.sizeUpR[k])`; fail bar (size only, §5.4) |
| `logic.bossState(w, i)` | padlock: `'recipe'` (ticket not done) / `'size'` / `'open'` |
| `bots.js` | target filtering and planning |
| `tools/slurp-pot/verify.mjs` | gates, margins |
QA test (Levels role, Node, `fit-test.mjs`): for 10,000 random `(r, a)` pairs with `r` and `needR(a)` in `[r0, rMaxShown]`, the HUD's `meterX(w.pot.r) >= meterX(needR(a))` iff `canFit(w.pot.r, a)`; outside that range it asserts only that the clamped meter value is 0 or 1. The padlock opens on exactly the step where `canFit` first becomes true with the ticket done.

### 3.3 Growth
```
on swallow start of item i:   mass += k_i · a_i²
                              r = min(cap, sqrt(r0² + G · mass))      // instant; G = 0.24
k = 1.0 junk (food or object) · 0.25 ingredient while its ticket line is open (bakeoff: 25 %)
  · 0.6 hedge/fence pieces · 0 boss
```
- An ingredient beyond its line's count is ordinary food (`k = 1`, no glow).
- **SIZE UP** fires each time `step(r) = floor(log(r / w.pot.r0)/log 1.25)` increases, i.e. each time `r` reaches the next entry of `w.pot.sizeUpR`. `createWorld` computes `w.pot.sizeUpR[k] = r0 × 1.25^k` (k = 1…, until > cap) once per level by repeated multiplication, so `step` only compares (`while (r >= sizeUpR[w.pot.step + 1]) w.pot.step++`) and never calls `Math.log`. Steps count from the level's own r0 (L1 0.25 → SIZE UP 1 at 0.3125). Steps are camera/juice beats only: no numbers shown.
- The drawn rim `rVis` eases toward `r` with `τ = 0.12 s` (render-only). Tipping animation uses `rVis` for looks; logic never reads `rVis`.

### 3.4 Swallow, block, bump (the fake physics)
- **Swallow start:** item idle, `fits` true, boss rules satisfied, Simmer not refusing, and centre distance `d < rEff − 0.25·a`. → `st = 1` (tipping), growth credited **now** (meter and ticket respond on the same frame as the bite SFX).
- **Tip (0.5 s, sim time):** progress `p` 0→1. Item centre slides to the pot centre with `ease = p²` (follows the moving pot), tilts toward the centre up to 70° (`tilt = 70°·smoothstep(0, 0.6, p)`), and sinks `y = −h·1.2·smoothstep(0.35, 1, p)`. Scale constant (sinking into the stew sells the depth). Blob shadow fades out over the first 0.15 s.
- **Despawn:** at `p = 1`, `st = 2`; the item is swap-removed from its kind's dense instance list (render, §13.3); in levels its SoA slot is never reused; in Feast a slot with `st = 2` for ≥ 1 s is reused by the spawner (`spawn {i, kind}`); 4–8 crumb particles in the item's main colour pop from the stew; items with `a ≥ 0.5·r` also play `glug`.
- **Solid** = every non-decor item whose `fits` flag is false (`catalog.solid` is removed; there is no per-kind solid flag). Bosses while locked are solid by this rule. Exception: under a Simmer cap, refused junk with `a < 0.5·r` is shoved, not solid (§4.5).
- **Block:** a solid item keeps the pot centre at distance ≥ `a + 0.5·r` (`BLOCK_K = 0.5`): the rim visibly tucks under the prop. Resolved in 2 passes over a spatial hash (cell 2 u).
- **Bump:** approach speed into a blocker > 1.2 u/s and 0.35 s cooldown → `bump` event (pot squint, thonk SFX, 6-px screen nudge, haptic 10 ms).
- **Locked boss bump:** additionally `bossNudge {why:'recipe'|'size'}` → the padlock rattles; if `'recipe'` the ticket jiggles and the missing ingredient's ring pulses; if `'size'` the meter's boss mark pulses. This is the wordless "why can't I eat it" answer (playtest: padlock not understood until bumped).

### 3.5 Recipe tickets
- Each level has 1 ticket (2 in two-course levels). A ticket = 1–4 **lines**, each `{kind, need}` (e.g. Tomato ×3). Ingredients are ordinary items flagged `ing:true` and drawn with the ingredient glow (§7.5).
- Swallowing an ingredient of an open line: `got++`, the line's progress ring fills, the icon pops; line complete → tick stamp on the line + `line` SFX. All lines complete → `ticketDone` → the boss's first lock (recipe) opens; the padlock pops only when the size condition is also met.
- **From L4**, at least one line's items sit behind a size gate (pens: hedge ring, fence, parked-car row, with a smaller **gate piece** that becomes swallowable at a known size) or ≥ 60 % of the map's depth away from spawn, so route order matters (§4.2).
- Ticket line kinds per town come from the catalogue (§4.6). Max 4 lines; max need 6 per line.

### 3.6 Boss and the boss bite
- One boss per ticket. Padlock billboard above it while locked.
- **Goal reveal** (every level, first attempt only; retries skip it): 0.0–0.7 s the camera is framed on the boss and padlock (L4+: also the first gate) while the ticket swings in; 0.7–1.3 s glide to the pot camera. Input is live from frame 0; the first touch cuts straight to the pot camera. Twist intros use this beat with the twist object first, then the boss (replaces the old 1.8 s intro beat). The timer still starts on the first input (§3.8). In play the boss is in view or has a persistent edge arrow (§7.6).
- `bossState(w, i)`: `'recipe'` until the ticket is done; then `'size'` until `canFit(w.pot.r, boss.a)`; then `'open'` (one-way; pot never shrinks except Simmer's cap, which never drops below the boss).
- **Padlock pop** (on `'open'`): shackle flips open with a click, padlock shrinks into a sparkle, the boss gets a pulsing gold outline glow (`#FFD34D`, 1.6 Hz), an arrow points at it if it is off-centre, the pot goes wide-eyed with a drool sparkle.
- **Boss bite** (swallow start on a boss): sim slow-mo 0.3× for 1.2 s *real* time; camera pushes in 10 % then shakes (amplitude 0.12·r, 0.25 s, decaying); boss tips over 0.5 s sim (≈ 1.67 s real) with a giant `glug`; 70 confetti; at the end the "ORDER UP!" service bell rings and the ticket slides to screen centre and is stamped. Win card at +1.6 s after the stamp. Two-course: the first boss plays the bite without the win; ticket 2 slides in from the right; play continues at normal speed.
- `P.happyTime()` on every final boss bite.

### 3.7 Chain and sizzle
- A **chain** is consecutive swallow starts each within `CHAIN_WIN = 0.7 s` (sim) of the previous. `n` starts at 1.
- Each bite's pitch steps up the ladder by chain index (§8.2). Badge "×n" appears near the pot from n = 3, scales 1.0→1.25→1.0 per increment, colour stays gold (number is the signal).
- **Sizzle:** when `n` reaches 10, and every further 5 (15, 20, …), add **+1 s** to the timer, pop "+1s" over the timer ring, play `sizzle`. Cap: total sizzle per level ≤ 10 % of `T`. Sizzle also gives +2 coins.
- Chain ends after 0.7 s without a bite (`chainEnd {n}`; badge drops away). `best` chain is recorded for the win card.

### 3.8 Timer, stars, win, fail
- Level timer `T` (s) per level (§4). **Starts on the first input with `m > 0`** (`start` event). Before that the ring is full and breathes (scale 1.0↔1.04 at 1 Hz). L1 has no timer at all (ring hidden, unfailable).
- Timer counts sim time; stops whenever the sim stops (Pause card, host pause, context loss); slow-mo scales it.
- **Stars** from time left at the final boss bite: `left = (tLeft − w.freezeAdded − grace)/(T − grace)` (Freeze seconds never count; sizzle seconds do; grace is the level's grace, L2 to L10 in §4.4, plus any mercy); **3★ if left ≥ 0.35, 2★ if ≥ 0.15, else 1★**. A win after the fail-card Freeze continue is always 1★. The Daily "≥ 30 % time left" line uses the same `left`. (Proto: 0.40/0.20. Lowered so the planner's 3★ is reachable while greedy lands in 2★ territory at the 70–85 % used target.) L1 always 3★.
- **Win:** final boss swallowed.
- **Fail: out of time** (`tLeft ≤ 0`). **Fail: spoiled** (soft-lock): `doomed(w)` (checked every 0.25 s sim) is true when (a) any open line's `need − got` exceeds the count of remaining reachable items of that kind, where reachable = `st ∈ {0, 1, 3}`, gull-nest items, or respawning rollers (lost items never count; no geometry test), or (b) the upper-bound reachable radius `sqrt(r² + G·Σ k·a² over all alive non-boss items)` is below `needR(boss.a)`. Spoiled shows the loss animation then the fail card within ≤ 2.0 s of the cause ("Spoiled!").
- **Mercy** (`mercy.js`, played by game.js on campaign levels and the Daily; Feast gets none): a time-out raises the step by 1, up to 3. Step k adds `k × round(0.3 × (T − grace))` seconds to both `T` and `grace` at the next start, so a retry gets more time and the stars keep the old pace. Steps 2 and 3 also start the pot bigger (`level.r0` × 1.1 and × 1.15, `level.mercyGrow`). A spoiled fail raises nothing, because time cannot help it. **Carry:** a win hands step − 1 to the next level through `save.help` (0 to 2), so a slow hand who needed step 3 starts the next level at step 2, and a hand who wins first time drops back to 0. A level or Daily that is new to this session starts from `save.help`, so the Daily takes the same carry; moving to another level without a win goes back to `save.help` too. `tools/slurp-pot/slow-hand.mjs --table` plays `withMercy()` as the game does and prints the table, the carry walk and sample Dailies. DECISION (11-06 Fri, round 2): MERCY_STEP 0.3, down from 0.4, because 0.3 meets the targets: the slow hand averages 1.50 tries a level on L2 to L10 (0.4: 1.47) and 2.01 over the whole walk (1.94), 119 tries in all (114), and wins a sample Daily by try 3 in 94 % of runs (99 %), 87 % on the hardest sample, with a mean of 2.65 tries. Table: `studio/2026-11-06/fix2/mercy-table.txt`.
- Low time: at 10 s the ring turns from gold to tomato and pulses; last 5 s `tick` SFX per second; pot eyes go worried. (Colour plus pulse plus sound: never colour alone.)

## 4. Level list

### 4.1 How levels are made
1. **10 hand-built archetypes** (`levels.js`, Levels role): each is a function `arch(spec, rng) → layout` that places zones, walls/pens/gates, lanes, belts, roost and the boss, in coordinates normalised to the map size, then hands item slots to the filler.
2. **Seeded filler/remix generator** `genLevel(spec, seed)`: fills each zone from the spec's tier budget, places ingredients per the recipe rules (§4.2), applies town catalogue, enforces readability and density rules, mirrors left/right when `seed & 1`. Deterministic per D7.
3. **Offline verification** `node tools/slurp-pot/verify.mjs`: expands every spec, runs the bots (§5.2), and either accepts, or bumps the seed (`seed += 7919`, max 40 tries), or fails with a report. `tools/slurp-pot/tune.mjs` sets `T = ceil(greedyTime / uTarget)` in 1 s steps (not ceil5) and re-verifies. Every level and the next 400 dailies × 3 variants must pass the gates in §5.3 before Wednesday night. Runtime: `verify.mjs --jobs 8` (worker_threads), sequential early stop once a gate is decided at 95 %, results cached by (spec hash, logic.js + bots.js hash); levels and dailies are separate commands (`verify.mjs --levels`, `verify.mjs --dailies`, the latter budget < 20 min on the M4). `sim-test.mjs` prints µs/step and fails if > 15 µs at 240 items in Node.

**Archetypes** (`W`, `D` = map width and depth; spawn at `(0, z1 − 2)`; boss toward `z0`):

### 4.2 Generator rules (all enforced, all checked by `verify.mjs`)
- **Spawn density:** ≥ 8 swallowable items within 2.5 u of spawn and ≥ 1 swallowable item within 1.2 u in every 45° sector (bites within the first 2 s of travel in any direction).
- **Boss visibility:** the goal reveal (§3.6) shows the boss; the persistent edge arrow (§7.6) covers it in play. Ingredients of every line: ≥ 1 visible or arrow-indicated within the first 3 s after the reveal.
- **Ingredient placement (from L4):** ≥ 1 line entirely behind a gate (pen, wall, car row, or on a belt/lane past a gate), or ≥ 60 % of `D` from spawn. Ingredient count per line = `need + spare` where spare = 1 (L1–L19), 1 for gated lines and 0 for open lines (L20+), and fragile lines always keep spare ≥ 1 (so only a second mistake can spoil). A fragile stack carries ≤ 1 item per line (§4.5). Gull lines need no extra spare: a stolen item goes to the nest and stays reachable (§4.5).
- **Growth margin:** `supply = Σ k·a²` over all non-boss items; `needMass = (needR(bossFinal)² − r0²)/G`. Margin `supply/needMass` ∈ [2.4, 3.0] L1–L5, [1.8, 2.4] L6–L20, [1.5, 2.0] L21–L40, [1.3, 1.7] L41–L60.
- **Contrast:** every T0/T1 item sits on a surface whose luminance differs from the item's main colour by ≥ 0.25 (relative luminance, sRGB → linear). T0 items are placed only on cloth/path/boards/plates (never lawn grass). Fixes "berries vanish on green".
- **Perf:** ≤ 240 items, ≤ 18 prop kinds (bosses count), ≤ 40 decor instances; no two items overlap (`dist ≥ 0.9·(a_i + a_j)` except stacks/belts); nothing within 0.3 u of the board edge.
- **Reachability:** planner bot wins with ≥ 15 % time left, and the greedy bot wins (§5.3).
- **Gate pieces:** `gate.a = 0.97 × FIT × rGate` where `rGate` is the radius the greedy bot reaches at 35–60 % of its run. Every wall piece of that pen / wall / car row / rope line is the same kind scaled uniformly to `wall.a = max(catalog.a, 1.25 × gate.a)` (height scales with it). Spacing `0.58 × 2 × wall.a`, so the pot cannot slip through. Verify: `gate.a × 1.2 ≤ min(wall.a)`, and the pen interior is unreachable for `r < needR(gate.a)`.

### 5.2 Bots (`bots.js`, shared by game, tools and `__qaBot`)

|---|---|---|---|---|---|

### 5.3 Verification gates (`verify.mjs`; any failure = level rejected)
1. L1 to L20: greedy wins (deterministic run) and with 20 seeds of ±3° noise wins ≥ 98 %. **Levels with snack piles (L21+): the average bot wins ≥ 90 % and the expert ≥ 99 %.** Greedy is printed there and gates nothing: a deterministic greedy loss is allowed on piles (DECISION 11-06 round 3; piles hand greedy 20 s or cost it the level, so it says nothing about the player).
2. L1 to L20: greedy time used / `T` within the level's Greedy % ± 4 (L10+: 70–85 %, bakeoff call). **Levels with snack piles (L21+): the average bot's spare time, median of its runs as % of `T` (a loss counts 0; Sizzle and chili seconds are in it), inside the tension band: peaks and milestones (L29 30 33 37 40 44 49 50 54 57 60) 16–26 %, normal levels 26–34 %, breathers (L25 35 45 55) 35 % or more.** DECISION 11-06 (mobile designer's tension curve): piles speed the bots unevenly, so greedy stopped measuring pace there. DECISION 11-06 round 3: the first band (peaks 8–14, normal 20–30) left casual 1–19 % on peaks; a peak's `T` now comes from casual (gate 4) and this band follows it. The average 3★ ceiling is off on pile breathers, because 35 % spare is the 3★ line itself.
3. **From L8: (a) deterministic planner time ≤ 0.80 × greedy time (L4–L7 ≤ 0.88; L21–L40 ≤ 0.78; L41–L60 ≤ 0.76 per §5.1), so the planner finishes with ≥ 35 % left (3★) while greedy gets 2★; (b) average-bot 3★ share 15–40 % per band, casual-bot ≤ 15 %; on the piles the floor is 5 on normal levels and 0 on peaks, ceiling unchanged; (c) still report the bakeoff ratio.** On the piles (a) is the planner earning 3★ outright, because greedy no longer measures pace there. If (a) fails after 40 seed bumps, verify.mjs moves the largest open line behind the nearest gate (or to ≥ 70 % of D) and re-runs; it never raises T to pass (a).
4. Casual win within ± 7 of target; average ≥ band floor; expert ≥ band floor. **Levels with snack piles: peaks and milestones keep goal ± 7 (goal 52, so 45–59), normal levels 60–92, breathers 85 or more; the average and expert floors are gate 1 there.**
5. Generator rules §4.2 (density, visibility, contrast, perf, margin, food share, no overlaps).
6. `doomed()` false at t = 0; a single crack never makes the level doomed (fragile spare); any number of gull steals never does (nest items stay reachable). Simmer levels: casual-bot boils ≤ 10. Daily: 400 days × 3 variants pass gates 1, 4 (casual ≥ 80 %), 5 and 6, and the average bot can meet each day's star lines.
7. Determinism: expanding the spec twice gives byte-identical JSON; the bot replay of the stored greedy input log reproduces the same finish time to 1 ms.
Output: `studio/2026-11-02/prod-levels/levels-report.md` with one row per level (all stats) + `levels-data.js` `stats` fields.

### 5.4 Fail feels fair (rules)
- Timer starts on first touch; L1 has no timer.
- The goal reveal shows the boss (and from L4 the first gate) at 0 s; in play nothing that matters is off-screen without an arrow (§7.6).
- Every threat is telegraphed: gull shadow 1.6 s + squawks; fragile near-wobble and rattle before contact, crack only above 2.0 u/s; rollers visible on their lane ≥ 1.5 s before reaching the pot; trucks horn before leaving a stop.
- No runtime randomness: everything moving is a function of level time and seed. Same input → same result.
- Soft-locks end in ≤ 2 s with "Spoiled!" (never a timer run-out after the level became impossible).
- Sim dt is fixed (1/60) and `dtReal` is clamped to 0.134 s; a hitch or tab switch never eats seconds (the sim stops on host pause and on a hidden tab).
- **Near miss by design:** L3 and L7 (the first two hard levels now that L5 is easy) are tuned so 60–75 % of casual-bot fails meet the SO CLOSE rule below. The verify report lists `nearMissShare` (SO CLOSE rule) for L3–L7; target ≥ 0.6 on L3 and L7.
- **The near-miss fail card** (§9.4): **the bar shows size only**: `size = meterX(r) / meterX(needR(boss.a))`, with the reached point and the boss silhouette at the end; the ticket's rings show the lines. Copy: size ≥ 0.9 and ≤ 1 ingredient missing → "SO CLOSE!"; size ≥ 0.7 or ≤ 2 ingredients missing → "Almost!"; else "Out of time!". `logic.progress()` keeps the size/recipe blend for analytics (`bar`) only. One big RETRY; Freeze "+10 s" if available.

## 6. Score
`P.best(score)` receives
```
score = 100 × totalStars + 10 × levelsBeaten + min(99, feastBest)
```
(`totalStars` ≤ 180, `levelsBeaten` ≤ 60, `feastBest` = most tickets in one Feast run.) Each term only rises, so the integer only rises (max 18,699). Called once on boot after `initMeta()`, after every level win, and after every Feast run. Never from daily (daily doesn't change it). Playables `sendScore` = this saved best.

### 7.4 Camera
- Perspective FOV 40°, **pitch 55°** (looking down), yaw 0. Target = pot position; the pot sits at **60 % of the safe rect's height from the top** (hero framing, bakeoff call) by offsetting the look-at point toward −z.
- **Goal reveal** (§3.6): 0.0–0.7 s the camera frames the boss + padlock (L4+: and the first gate; twist intros: the twist object first) so they fill the safe rect's middle 60 %; 0.7–1.3 s it glides (ease in-out) to the follow pose. The first touch snaps to the follow pose. Skipped on retries.
- Visible world width at the pot: `Wv = 3.6 + 7.2·rCam` (render only; the sim uses the radius-only `VIEW_R`/`SEE_R`, §13.3), where `rCam` eases toward `w.pot.r` with τ 0.45 s. SIZE UP adds a **punch**: `Wv × 1.08` for 0.5 s (ease out), on top of the zoom-out. Landscape uses `Wv × 1.35` (wider view).
- Follow: critically damped spring on position, ω = 9 rad/s; **no velocity lead**. Clamp so the board edge never shows more than 2 u of table.
- Boss bite: push-in 10 % over 0.3 s real, shake 0.12·r for 0.25 s (decay), restore over 0.6 s.
- Readability: **minimum on-screen size 10 CSS px** for T0 items; if `a × pxPerU < 5`, the instance is drawn with a scale boost up to 1.6× (render-only; logic unchanged). **Open-line ingredients are drawn at ≥ 14 CSS px diameter** (render boost up to 2.5×, logic unchanged). `pxPerU` is computed every frame from `Wv` and the canvas CSS width.

### 7.5 Item readability rules
- **Edible rim light:** items with `fits` true within `3·r` of the pot get `aGlow` easing to 1 (0.15 s): white fresnel `#FFFFFF` at 0.55 + 4 % brightness. Too-big items get nothing. Edible vs too-big reads by light, never by colour alone.
- **Ingredients** (open line): drawn at ≥ 14 CSS px diameter (§7.4); a soft gold halo ring decal under the item (`#FFD34D`, pulsing 1.2 Hz, radius `max(1.6·a, 11 px / pxPerU)`, one instance of the markers mesh) + a tiny ticket-icon billboard above it when within 6 u; ingredients that do not yet fit still show the halo (so you know where to go) but no rim light.
- **Gate pieces:** dashed white outline decal + a hinge decal; tick on the meter (§9.3).
- **Boss:** padlock billboard (kie `icon-padlock`) while locked; gold pulsing glow when open.
- **Contrast:** T0/T1 never on same-hue ground (§4.2).
- **Occluder fade:** any prop whose screen-space box covers the pot (ray from camera to pot centre and to rim points ±x hits its bounding cylinder) fades `aAlpha` to **0.40** over 0.15 s with a 4×4 Bayer **dither** (no transparency sorting; stays in the opaque pass) and back over 0.3 s when clear.
- **Off-screen arrows** (§7.6): boss and required ingredients.

## 8. Audio bible
All procedural Web Audio (`audio.js`), no audio files. One `AudioContext`, resumed on the first user gesture (and on `P.onAudio(true)`).

### 8.1 Music: one loop per town (8 bars, scheduled 0.2 s ahead with a look-ahead timer)

- Each loop's bars are chosen by a seeded pattern so 8 bars repeat every ~18 s without obvious looping (two melody variants alternate A A B A).

### 8.2 Bite pitch ladder (kitchen-foley pentatonic)
`bite` = **clink** (sine f, 30 ms decay + sine 2.76f at 0.35, 40 ms) + **click** (noise 4 kHz highpass, 8 ms) + **crunch** (noise 1.2 kHz bandpass Q 2, 50 ms, gain 0.4) — a spoon-on-pot + crunch, not a synth beep.
- Base `f` by tier: T0 **660 Hz**, T1 **550**, T2 **440**, T3 **330**, T4 **220** (bigger = deeper; T3+ add `glug`).
- Chain ladder: multiply `f` by the pentatonic step `[1, 9/8, 5/4, 3/2, 5/3, 2, 9/4, 5/2]` at index `(n − 1) mod 8`, with **+1 dB per completed cycle** of 8 (max +3 dB). Top note ≤ 1.65 kHz (660 × 5/2), so long chains never get shrill.
- Rate limit: max 1 bite sound per 45 ms (others coalesce into the next with +2 dB); voice pool 10; one shared 1 s white-noise buffer for all noise sources.

### 8.4 Mix, ducking, mute, pause
- Master → `DynamicsCompressor(threshold −12 dB, ratio 4, attack 3 ms, release 150 ms)` → destination.
- Buses: **music 0.32**, **sfx 0.85** (× settings sliders `set.music` default 0.7, `set.sfx` default 0.9; separate sliders on Settings).
- Ducking: `bossBite`, `orderUp`, `win`, `fail` duck music to **45 %** (attack 50 ms, release 600 ms).
- `P.onAudio(on)` and the mute button (web only, `P.showMute`) set master gain 0/1 with a 50 ms ramp; `P.onPause()` (host) and the Pause card suspend the context; `P.onResume()` resumes only if not muted. Record mode: the AudioContext is never started; `__rec.audio(dur)` returns a base64 WAV of `dur` s of silence (music is added in the edit).

## 9. Screens and flows

### 9.1 Principles
- **One obvious next action per screen**: a single gold primary button (Enter/Space trigger it); everything else is paper secondary or small icons.
- **One callout at a time** (queue in `ui.js` `callout(id, icon, text, ms)`; priority: tutorial > twist > gift > milestone; a callout never covers the ticket, meter or pot).
- **Esc** closes the topmost card/dialog or opens/closes pause in play; never `preventDefault`ed. **P** toggles pause.
- All screens drawn on `#ui` canvas (D2); hit areas from `layout.js` rects; pointer events on `#ui` route to buttons first, then (in play) to the stick.
- Progress always visible: title shows "Level N" on PLAY and ★ total; map shows every node; HUD shows the level in the ticket header ("L7 · Hedge Maze").
- First-ever boot: title shows only logo + pot + giant **PLAY** (the gesture unlocks audio) → **L1 directly** (no map, no menus). Afterwards PLAY = continue at `cur` (next unbeaten level) directly; the map is one tap away.

### 11.3 Save schema (`v: 1`) and migrate
```js
const DEFAULT_SAVE = {
  v: 1, ts: 0,                      // ts = Date.now() of the last write (merge tiebreak)
  best: 0,                          // last value given to P.best
  stars: Array(60).fill(0),         // 0..3 per level
  cur: 1,                           // next unbeaten level (1..61; 61 = all done)
  coins: 50,
  boost: { magnet: 0, freeze: 0, mega: 0 },
  gifted: [],                       // booster-unlock gifts claimed: 'magnet'|'freeze'|'mega'
  skins: ['sunny'], wear: 'sunny',
  daily: { won: {}, streak: 0, last: '', ladder: 0, bestStreak: 0, starPot: false, lids: 0, lidCard: false },
                                    // won: {'2026-11-08': 3, …} (last 30 kept); ladder 0..6; starPot = Star Ladle earned;
                                    // lids = Streak Lids held (0..2, auto-used on a missed day); lidCard = show "Saved by a lid!" on next visit
  feast: { best: 0, bestBites: 0, plays: 0, ghost: [] },   // ghost: PB ticket-finish times (s), ≤ 99
  giftsClaimed: 0,                  // star milestones claimed (count of 15★ steps)
  chests: [],                       // 'picnic'|'market'|'harbour'
  set: { music: 0.7, sfx: 0.9, haptics: true, stick: null },   // stick null = auto (touch on, mouse off)
  tut: 0,                           // bit flags: 1 drag, 2 recipe, 4 padlock, 8 stars, 16 pens, 32 rolling, 64 fragile, 128 belt, 256 two-course, 512 simmer, 1024 gulls, 2048 truck, 4096 layered, 8192 freeze-offer
  stats: { bites: 0, bosses: 0, plays: 0, fails: 0, ms: 0, bestChain: 0 }
};
// meta.js exports DEFAULT_SAVE and migrate; game.js passes both to P.init.
function migrate(old) {                       // called by P.init only when old.v < 1 (platform rule: v < version)
  const s = structuredClone(DEFAULT_SAVE);
  if (!old || typeof old !== 'object') return s;
  if (old.v === 0) {                          // proto/greybox save: { v:0, best, lv }
    const lv = Math.max(1, Math.min(60, old.lv | 0));
    for (let i = 0; i < lv - 1; i++) s.stars[i] = 1;
    s.cur = lv; s.best = old.best | 0; return s;
  }
  return Object.assign(s, old, { v: 1 });     // forward-tolerant: unknown keys kept
}
```
**Deep fill and ownership:** platform.js fills defaults shallowly, so `initMeta(P)` deep-fills every missing nested key from `DEFAULT_SAVE` **in place on `P.data`** (this is how later fields such as `daily.lids` reach old v1 saves without a version bump). `P.save()` serialises `P.data`, so meta never holds its own copy: it mutates `P.data` directly, and after a cross-tab merge assigns `P.data = merge(P.data, other)`.
**Cross-tab merge** (`meta.merge(a, b)`, PLAYBOOK lesson): progress takes the max or union (`stars[i]` max, `cur` max, `best` max, `skins`/`gifted`/`chests` union, `daily.won` key union with max stars, `daily.bestStreak` max, `daily.starPot` OR, `feast.best` max with that side's `ghost`, `feast.plays`/`stats.*` max, `giftsClaimed` max, `tut` OR); spendables and settings (`coins`, `boost`, `wear`, `set`, `help`, `daily.streak/last/ladder/lids/lidCard`) come together from the newer `ts`. Run before every save and on `P.onStoredChange`. Save size < 4 KB (limit 500 KiB).

### 13.5 Frame order (`game.js`)
```
raf(now):
  dtReal = min(DTREAL_MAX /*0.134*/, (now − last) / 1000); last = now
  if paused: ui.draw(...); return                                  // Pause card: no sim, no audio (host pause stops raf entirely, §11.1)
  if slowT > 0: slowT −= dtReal                                    // slowT is owned by game.js, never in w (record: −= 1/60 per frame)
  scale = slowT > 0 ? SLOWMO : 1                                   // bus bossBite {final:true} → slowT = SLOWMO_REAL (1.2 s real)
  acc += dtReal · scale; steps = 0
  while acc ≥ DT and steps < MAX_STEPS /*8*/:
      inp = bot ? bots.decide(bot, w, DT) : input.sample()
      logic.step(w, inp, DT); if feast: feast.feastStep(fs, w, DT)  // step 0 copies x,z,r → px,pz,pr and ix,iz → ipx,ipz
      acc −= DT; steps++
  if steps == MAX_STEPS: acc = 0                                   // drop backlog, never spiral
  for ev of w.events.splice(0): bus.emit(ev.type, ev)              // audio, render fx, ui, meta, state machine
  alpha = acc / DT
  render3d.update(w, dtReal, alpha); render3d.draw()              // lerps previous → current by alpha (smooth slow-mo too)
  ui.draw(state, w, dtReal)
  modes (record: __rec.step(n) drives the same accumulator path with dtReal = 1/60 and no raf; __rec.frame(q) draws)
```
Host resume sets `last = performance.now(); acc = 0` before restarting the loop (§11.1).

### 13.6 Boot order (kills the 19-fps startup hitch; firstFrame before any await)
1. CSS paper background; `#ui` draws the loading frame (logo + pot silhouette) synchronously, then **`P.firstFrame()`, before any await**. Fonts: `document.fonts.load('64px "Lilita One"')` raced against 1500 ms (index.html links `../shared/fonts.css`; build-playables strips `<link rel=preload>`, so nothing relies on it).
2. `await P.init({ store: 'sp_', version: 1, defaults: DEFAULT_SAVE, migrate })`, then `meta.initMeta(P)` (deep fill, lids for missed days).
3. `render3d.initRender(canvas, { tier })` (renderer, every material/program: prop material, pot, stew, pit, ground+hole stencil, surfaces, shadow, particles, markers, gull ≈ 10 programs identical for all towns; every InstancedMesh pool at `kindMax` capacity), then `levels.getLevel(meta.cur)` (or L1) and `render3d.loadLevel(...)`.
4. `await Promise.race([render3d.warmUp(), sleep(2500)])` (warmUp = `compileAsync` + 2 offscreen frames; if it loses the race it keeps compiling behind the title).
5. Title drawn, `audio.initAudio()` (graph built, context suspended), then **`P.ready()`** (it already calls loadingDone; never call `P.loadingDone()` separately).
6. Level switch: pools already exist (boot, `kindMax`), so `loadLevel` only refills the per-kind dense instance lists and, on a town change, rebuilds the merged static layer during the 0.25 s card-out animation; no InstancedMesh, material or InstancedBufferAttribute is ever created after boot.
QA: no frame > 50 ms in the first 10 s after the first input (CDP trace, 4× throttle), and first-level median ≥ 50 fps.
